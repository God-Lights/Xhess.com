# 전략 테마 표시 (Strategy Themes)

내 차례에 **이 포지션의 특징**(통과폰, 약한 폰, 나이트 전초기지, 킹 안전 …)을 보드에 색 원으로 표시하고, 그에 맞는
**추천 전략을 문장으로** 알려 준다. 앱의 "전략 테마" 체크박스로 켜고 끈다(기본 켜짐). 전략 마킹(수 화살표)과 함께 보인다.

## 무엇이 보이나
| 표시 | 의미 |
|---|---|
| 보드의 색 원 + 한 글자 | 그 칸의 기물/구멍이 평가에서 점수를 준(또는 깎은) 특징 |
| 패널의 추천 전략 | 영향이 큰 특징부터 최대 4줄. 앞의 배지는 나에게 어떤 의미인지: **내 강점**(활용) · **내 약점**(보완) · **상대 약점**(공략) · **상대 강점**(경계) |
| 항목 칩 | `내 통과폰 e5 +0.53` — 값은 **나에게 이로우면 +**. 눌러서 그 특징의 보드 표시를 켜고 끈다(내 것과 상대 것을 따로) |

| 테마 | 색 | 글자 | 칸 |
|---|---|---|---|
| 통과폰 | 청록 | 통 | 통과폰 |
| 막을 수 없는 통과폰 | 하늘 | ★ | 그 폰(상대 킹이 따라잡지 못함) |
| 겹폰 / 고립폰 | 주황 / 빨강 | 겹 / 고 | 해당 폰 |
| 나이트 전초기지 | 보라 | 전 | 상대 폰이 공격할 수 없는 칸의 나이트 |
| 열린·반열린 파일의 룩, 7랭크 룩 | 주황 계열 | 룩 / 7 | 그 룩 |
| 비숍 쌍 | 초록 | 쌍 | 두 비숍 |
| 킹 앞의 구멍 | 분홍 | 구 | 킹 앞에서 폰이 비어 있는 칸 |
| 킹 위협 | 진분홍 | 위 | 킹 주변을 겨냥한 상대 기물 |
| 갇힌 기물 | 갈색 | 갇 | 안전한 칸이 거의 없는 기물 |
| 외로운 킹 몰이 | 남색 | 몰 | 킹만 남은 상대 킹 |

예: 흑의 고립폰 d5 → 나(백)에게는 *상대 약점* → "상대 고립폰 d5을(를) 룩·퀸으로 겨냥해 압박하세요".

## 데이터의 출처: 평가 함수가 직접 알려 준다
테마는 앱이 따로 계산하는 것이 아니라 **Albatross 평가 함수가 점수를 줄 때 남긴 기록**이다. 그래서 표시되는 특징은 엔진이 실제로
점수에 반영한 것과 항상 일치한다. 평가 함수는 각 항목에서 "어느 칸이 얼마를 줬는지"를 함께 기록하고(`EvalMark`), UCI 의 비표준 `themes`
명령이 이를 (테마, 색)별로 모아 출력한다.

```
theme passed white e5 cp 53 mg 35 eg 70
theme isolated black a7,c7 cp -26 mg -24 eg -32
themes done phase 14 scale 128 white 31
```
`cp` 는 게임 단계로 보간한 값(그 색 관점, + = 그 색의 강점), `mg/eg` 는 중반/종반 값이다.

- **점수는 바뀌지 않는다.** 기록은 표시 전용이고, 탐색이 쓰는 평가 경로에서는 컴파일 시점에 사라진다(`Evaluator<false>`). `bench 9` 의 노드 수(1,784,550)와 NPS 가 그대로임을 확인했다.
- 대국 엔진과 **별개의 Albatross 워커**가 테마를 계산한다. 그래서 대국 엔진이 Stockfish 여도 같은 기준의 테마를 볼 수 있다(탐색이 없어 한 포지션에 수 ms).

## 구조
```
engine/src/eval/classical.cpp   평가 + EvalMark 기록, summarize_themes, format_themes
engine/src/uci/uci.cpp          themes 명령
app/src/themes.ts               파싱, 역할 분류(내 강점/약점, 상대 강점/약점), 추천 전략 문장, 보드 도형(순수 로직)
app/src/themeClient.ts          테마 전용 Albatross 워커(요청이 겹치면 마지막 것만 계산)
app/src/main.ts                 패널(문장·칩), 도형 두 층(추천 화살표 + 테마 원)
```

## 검증
- 엔진 테스트 93개(GCC·clang·ASan+UBSan·TSan): 알려진 포지션에서 테마별 정확한 칸과 값(통과폰, 막을 수 없는 통과폰 450, 겹폰·고립폰, 전초기지, 룩 파일·7랭크, 비숍 쌍, 킹 앞의 구멍, 킹 위협, 갇힌 기물, 킹 몰이),
  **기록의 합이 해당 평가 항목과 정확히 일치**(통과폰·전초기지·룩·비숍 쌍·종반 항목, 중반/종반 각각), 흑백을 뒤집으면 테마도 대칭(칸 포함), 기록이 점수를 바꾸지 않음, 출력 형식.
- 앱 테스트 86개: 파싱(잡음·모르는 테마 무시), 역할 분류(양쪽 관점), 추천 문장, 칩·도형, 브러시, `ThemeClient`(요청 병합, 시간 초과, 재시도, dispose).
- WebAssembly 빌드가 네이티브와 같은 결과를 내고(`themes` 포함), 브라우저(Chromium, Playwright, 실제 Stockfish 대국 엔진)에서 확인: 오프닝 수순으로 만든 포지션에서 비숍 쌍·킹 앞의 구멍·고립폰이 보드에 표시되고, 추천 화살표와 함께 보이며, 칩으로 켜고 끌 수 있고, 수를 두면 사라졌다가 다음 내 차례에 다시 계산된다.

## 알려진 한계
- **테마는 평가 함수가 보는 것까지만** 안다. 약한 칸(hole), 뒤처진 폰, 폰 폭풍, 오프닝 이론, 장기 계획 같은 것은 아직 없다. 추천 전략은 "수"가 아니라 "특징에 맞는 일반적 조언"이다.
- 문장은 규칙 기반 템플릿이다. 구체적인 최선의 수는 전략 마킹(화살표)이 알려 준다. 둘이 다른 말을 하는 것처럼 보일 수 있다(테마는 정적 평가, 화살표는 탐색 결과).
- 값은 가중치가 튜닝되지 않은 평가의 점수라 절대적인 크기보다 **순서와 부호**가 의미 있다.
- 갇힌 기물은 "백랭크를 떠났는데 안전한 칸이 거의 없는" 경우만 센다(시작 포지션의 미전개 기물은 세지 않는다).
- 테마 계산에는 Albatross 워커(WebAssembly)가 필요하다. 로드에 실패하면 패널에 안내가 뜨고 나머지 기능은 그대로 동작한다.
- 칸 표시는 원이라서, 같은 칸에 테마가 둘 이상 걸리면 겹쳐 보인다.
