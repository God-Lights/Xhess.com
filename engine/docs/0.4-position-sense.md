# Albatross 0.4 "Position Sense" — 설계 기록

범위: 평가 함수 개선. 0.3 까지는 "기물 값 + 위치표" 수준이었다. 0.4 는 **Tapered Evaluation**(중반·종반 두 값을
게임 단계로 보간)과 폰 구조, 통과폰, 기동성, 킹 안전, 기물 활동, 엔드게임 지식을 넣고, 항목별 점수를
설명할 수 있게(`EvalTrace`, UCI `eval`) 만들었다. 탐색은 그대로다. 같은 버전에서 **브라우저용 WebAssembly 빌드**도
처음 배포한다(`docs/albatross-web.md`).

## 구조
`evaluate(pos)` 는 0.3 과 같은 인터페이스(탐색은 이것만 안다). 내부는 항목마다 (중반, 종반) 점수 쌍을 계산하고 합친다.

```
score = ( mg × phase + eg × (24 − phase) ) / 24        phase = N·B 1, R 2, Q 4 의 합(시작 24, 최대 24로 제한)
```

## 항목
| 항목 | 내용 |
|---|---|
| Material | 폰 100/120, 나이트 320/300, 비숍 330/320, 룩 500/520, 퀸 900/920 (중반/종반) |
| Piece-square | 기물별 위치표. 폰·킹은 중반/종반이 다르다(폰은 종반에 전진이 핵심, 킹은 종반에 중앙) |
| Bishop pair | 비숍 두 개 +30/+50 |
| Pawn structure | 겹폰(−8/−18), 고립폰(−12/−16), 폰이 받치는 폰·나란한 폰(랭크가 높을수록 큰 보너스) |
| Passed pawns | 랭크별 보너스(중반 2~110, 종반 6~200). 앞이 막히면 절반. 종반에는 우리 킹이 가깝고 상대 킹이 멀수록 가산 |
| Mobility | 안전한 칸 수(자기 기물과 상대 폰이 공격하는 칸 제외) × 기물별 가중치 − 기준값 |
| Knight outposts | 폰이 받치고 상대 폰이 영영 공격할 수 없는 4~6랭크 나이트 +22/+12 |
| Rooks | 열린 파일 +25/+15, 반열린 파일 +12/+10, 7랭크 +15/+25 |
| King safety | 킹 앞 폰 방패(가까움 +10, 한 칸 뒤 +4, 없음 −12), 킹 옆 파일이 열려 있으면 감점, 킹 주변을 공격하는 상대 기물(N2 B2 R3 Q5 단위, 2개 이상일 때 `단위²` 감점, 퀸 없으면 절반) |
| Endgame | 상대에게 킹만 남았을 때 mop-up(상대 킹을 가장자리로, 내 킹을 가깝게), 스퀘어 규칙으로 못 막는 통과폰 +450, 서로 다른 색 비숍만 남은 엔드게임은 종반 값 50% |

가중치는 손으로 정한 출발점이다. 자동 튜닝(Texel/셀프플레이 기반)은 0.5 의 과제.

## 설명 가능한 평가
`evaluate_trace(pos)` 는 항목 × 색 × (중반/종반) 표를 돌려주고, UCI 의 비표준 `eval` 명령이 이를 출력한다.
항목별 점수는 이후 앱의 **전략 테마 표시**(약한 칸, 열린 파일, 통과폰, 킹 안전)의 재료가 된다.

## 검증 결과 (이 저장소에서 실제 측정)
- **엔진 간 대국** 0.4 vs 0.3, 200판, 수당 50 ms, 동시 4판: **+117 =37 −46, 점수 67.8%, Elo +129 (95% 구간 +85 ~ +177), LOS 100%.**
  종료 사유: 체크메이트 163, 3회 반복 18, 기물 부족 7, 50수 6, 300수 제한 5, 스테일메이트 1. 충돌·불법 수 없음.
- **속도 비용**: `bench 9` NPS 3.35 M → 2.21 M (평가가 풍부해진 대가, 약 −34%). 노드당 비용 증가에도 대국에서는 크게 이득이다.
- **단위 테스트 82개**: 항목마다(겹폰·고립폰·지지폰, 통과폰과 랭크·킹 근접, 비숍 쌍, 룩 파일, 기동성, 아웃포스트, 킹 방패와 공격자, mop-up, 스퀘어 규칙의 템포 경계, 서로 다른 색 비숍) 한 가지씩 확인하고,
  색 대칭(좌우·흑백을 뒤집어도 같은 점수)과 "항목 합 = 최종 점수"를 확인한다. GCC·clang·ASan+UBSan·TSan 에서 통과, Perft 는 그대로 정확.
- 시작 포지션의 평가는 0.00 (항목별 합계도 0).

## 한계
- **가중치는 튜닝하지 않았다.** 항목별 기여(예: 킹 안전만 끄고 대국)를 분리해 측정하지 않았다. +129 Elo 는 항목 묶음 전체의 효과다.
- Elo 는 이전 버전(0.3) 대비 상대값이며 짧은 시간 제어의 셀프플레이라 과대평가될 수 있다. 외부 엔진 대비 절대 강도는 측정하지 않았다.
- 폰 구조는 뒤처진 폰(backward), 폰 폭풍, 약한 칸(hole)을 아직 보지 않는다. 킹 안전은 단순한 공격 단위 모델이다.
- 스퀘어 규칙은 "상대에게 기물이 없고 앞길이 비어 있을 때"만 본다. 킹+폰 엔드게임 전체(opposition 등)를 아는 것은 아니다.
