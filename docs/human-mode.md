# 인간 모드 (Human Mode)

엔진이 **사람처럼** 둔다: 대부분은 좋은 수를 두지만 가끔 차선을 고르고, 가끔은 **희생(sacrifice)** 을 한다.
희생은 평가를 보면 **탁월한 수(!!)** 일 수도, **블런더(??)** 일 수도 있다. 앱의 "엔진 모드 → 인간 모드"로 켠다.

## 슬라이더
| 슬라이더 | 의미 |
|---|---|
| 실수 빈도 (0~100) | 높을수록 최선이 아닌 수를 자주 둔다. 0 은 거의 항상 최선. |
| 희생 성향 (0~100) | 높을수록 손해가 큰 희생도 자주 시도한다. 0 이면 손해 큰 희생은 절대 두지 않는다(정확한 희생은 평소처럼 둘 수 있음). |

인간 모드에서는 "난이도" 슬라이더 대신 위 두 개를 쓴다. 설정은 브라우저/앱에 저장된다.

## 엔진이 희생했을 때의 알림
둔 수가 희생이거나 큰 실수면 패널에 알림이 뜬다. 평가는 엔진이 그 수를 분석한 점수를 **그 순간의 엔진 최선과 비교한** 값이다.

| 표시 | 조건 |
|---|---|
| **!!** 탁월한 희생 | 희생(교환 이상)인데 최선 대비 손해 ≤ 0.40 |
| **!** 정확한 갬빗 | 폰 하나를 내주는데 손해 ≤ 0.40 |
| **?!** 도박성 희생 | 희생이고 손해 0.40 초과 ~ 1.50 |
| **??** 블런더 | 희생이고 손해 1.50 초과 |
| **?** 실수 | 희생이 아닌 수인데 손해 1.50 초과 |

희생의 종류: 폰 갬빗, 교환 희생(룩↔마이너 정도), 기물 희생, 대형 희생. 내 차례에는 "전략 마킹"이 켜져 있으면 엔진의 희생을 **어떻게 응징할지**(추천 화살표)도 바로 볼 수 있다.

## 어떻게 고르나
1. **상위 후보 분석**: 엔진(`MultiPV` 6개, 약 1초)으로 좋은 수들과 점수를 구한다.
2. **희생 수 평가**: 희생 성향이 0 보다 크면, 상위 후보에 없는 희생 수 중 최대 3개를 골라(체크·포획·큰 희생일수록 뽑힐 확률↑) `searchmoves` 로 따로 평가한다. 블런더급 희생은 상위 후보에 거의 나오지 않기 때문이다.
3. **선택**: 후보 전체에서 확률적으로 하나를 고른다.
   - 기본은 손해에 대한 소프트맥스. 온도는 `3 + 197·실수빈도²` 센티폰(0 → 거의 항상 최선, 0.4 → 약 35, 1 → 200).
   - 손해가 큰 희생은 평소 후보에서 빠지고, **"희생하고 싶은 기분"**(확률 `0.4 × 희생성향`)일 때만 후보가 된다. 그때도 덜 나쁜 희생을 더 선호한다.
   - 이길 수 있는 **짧은 메이트(3수 이내)는 놓치지 않는다.**
4. **분류**: 둔 수의 희생 여부와 최선 대비 손해로 위 표처럼 분류한다.

### 희생 판정
수를 둔 뒤 **물질 변화** = (이 수로 잡은 값) − (상대가 한 칸에서 얻을 수 있는 최대 교환 이득). 교환 이득은 정적 교환 평가(SEE: 가치가 낮은 기물부터 번갈아 잡고, 잡힌 기물 뒤의 슬라이더 x-ray 반영)로 계산하고, 킹은 상대가 그 칸을 더 지키면 잡지 못한다. **체크를 주는 수는 상대가 체크 응수만 할 수 있으므로** 합법 응수 중 포획만 본다. 폰 하나(1.00) 이상을 내주면 희생으로 본다.

## 구조
```
app/src/humanmode.ts   순수 로직: 희생 판정(SEE), 후보 풀, 선택(chooseMove), 분류(classify)
app/src/humanplay.ts   pickHumanMove(): 엔진 분석(MultiPV, searchmoves)으로 후보를 모으고 고른다
app/src/main.ts        엔진 모드·슬라이더, 엔진 차례에 연결, 알림 표시
```
표준 UCI(`MultiPV`, `searchmoves`)만 쓰므로 Stockfish(WASM·네이티브)와 Albatross 모두에서 동작한다.

## 검증
- 단위 테스트: 희생 판정(퀸·기물·교환·폰 갬빗, 체크·킹 합법성 반영), 후보 풀, 선택 확률(희생 성향 0 이면 손해 큰 희생 0%, 클수록 증가, 덜 나쁜 희생 선호, 블런더도 가끔, 짧은 메이트는 항상 선택, 같은 시드는 같은 선택), 분류 경계값, 가짜 UCI 엔진으로 `pickHumanMove` 전체 흐름(희생 수만 `searchmoves` 로 평가, 취소, 옵션 복원).
- 브라우저 E2E(Playwright, 실제 Stockfish WASM): 난수를 고정해 "희생하고 싶은 기분"을 강제한 국면에서 엔진이 실제로 `Nd4??`(기물 희생, 최선보다 6.94 불리)를 두고 알림이 표시됨. 일반 난수로 3수 두는 동안 엔진은 항상 합법 수로 응답했고 도박성 희생(`f6?!`), 폰 갬빗 블런더(`e5??`)도 나왔다.

## 알려진 한계
- **분류는 엔진의 짧은 분석 기준이다**(상위 후보 약 1초, 따로 평가한 희생 수 약 0.25초). 더 깊이 보면 판정이 바뀔 수 있다. 특히 따로 평가한 희생 수는 짧게 본 점수라 "블런더"가 과장될 수 있다.
- 희생 판정은 **한 칸의 교환**과 체크 응수만 본다. 여러 칸에 걸친 콤비네이션이나 장기적 보상(포지션 희생)은 희생으로도, 탁월함으로도 알아보지 못한다. 핀은 무시한다.
- 엔진이 두는 순간 일부러 나쁜 수를 두는 것이라 "어디가 사람 같은가"는 단순화된 모델이다(실수는 점수 차에 비례, 희생은 확률적). 사람의 실제 실수 분포(시간 압박, 시야 협착 등)와는 다르다.
- 한 수에 약 1.3~2초가 걸린다(분석 후 선택).
- 인간 모드는 앱(UI)의 기능이다. Albatross 자체에 UCI 옵션으로 넣은 것은 아니라서, 다른 GUI 에서 Albatross 를 쓸 때는 적용되지 않는다.
