# Albatross 0.3 "Deep Flight" — 설계 기록

범위: 같은 시간에 더 깊이 보는 탐색. 전치 테이블, 수 정렬(TT·SEE·killer·history), PVS, LMR, Null-Move Pruning,
체크 연장, `Hash` 옵션. 평가 함수는 0.2 그대로다(0.4 에서 개선). 아래는 **구현된 결정**과 **측정 결과**다.

## 구현

| 기능 | 내용 |
|---|---|
| 전치 테이블 | Zobrist 키로 이전 결과 재사용. 슬롯당 12 바이트(키 상위 32 비트·수·점수·깊이·세대/바운드). 인덱스는 키 하위 비트(2의 거듭제곱 크기). 교체: 같은 탐색 세대의 훨씬 깊은 항목은 보존, 오래된 세대는 항상 교체, 실패-낮음 노드는 이전 최선수를 유지. PV 노드에서는 TT 컷오프를 하지 않아 PV 가 끊기지 않는다. |
| 메이트 점수 | TT 에는 "이 노드 기준" 메이트 거리로 저장하고 꺼낼 때 현재 ply 로 환산 → 다른 ply 에서 만난 같은 국면도 정확한 `mate N`. |
| SEE | 교환 시퀀스를 최소 가치 공격자로 시뮬레이션(스왑 리스트, x-ray 반영, 킹은 큰 값으로 처리). 핀은 무시. 정렬에서 좋은/나쁜 캡처를 가르고 quiescence 에서 손해 보는 캡처를 건너뛴다. |
| 수 정렬 | TT 수 → 좋은 캡처(MVV-LVA) → killer 2개 → history → 나쁜 캡처 → 언더프로모션. history 는 중력(gravity) 공식으로 갱신하고 컷오프 수에 보너스, 먼저 시도한 조용한 수에 페널티. |
| PVS | 첫 수는 전체 창, 나머지는 널 윈도우 → 알파를 넘으면 재탐색. |
| LMR | 깊이 ≥ 3, 4번째 이후 조용한 수, 체크 중이 아니고 체크를 주지 않는 수만. `0.75 + ln(d)·ln(i)/2.25`, PV 노드·killer 는 1 줄임. 알파를 넘으면 전체 깊이로 재탐색. |
| Null-move | 깊이 ≥ 3, 체크 아님, 비폰 기물 있음(zugzwang 방지), 연속 널무브 금지, 정적 평가 ≥ beta. `R = 3 + depth/4 + min((eval-beta)/200, 2)`. 증명되지 않은 메이트 점수는 반환하지 않는다. |
| 체크 연장 | 체크 중인 노드는 깊이 +1 (체크 중 quiescence 로 떨어지지 않게). |
| UCI | `Hash`(1–4096 MB, 기본 16), `Clear Hash`, `info hashfull`. `ucinewgame` 은 TT 를 비운다. 비표준 `status` 명령(대국 판정용). |
| 코어 | `Position::do_null_move/undo_null_move`(ep 해제, 키·50수·체커 갱신). |

의도적으로 **넣지 않은 것**: aspiration window, reverse futility/futility pruning, 카운터무브, 멀티스레드(Lazy SMP), TT 의 quiescence 사용.
각 항목은 개별로 켜고 끄며 측정하지 않았다(아래 한계 참고).

## 측정 방법: `tools/match.py`
외부 의존성 없는 엔진 간 대국 도구. 짧은 오프닝 16개를 색을 바꿔 두 번씩 두고, 규칙 판정은 엔진의 `status` 명령
(Perft 로 검증된 수 생성, 3회 반복, 50수, 기물 부족)으로 한다. W/D/L, 점수, Elo 차이와 95% 구간, LOS 를 출력한다.

```bash
python3 engine/tools/match.py --a <새 엔진> --b <기준 엔진> --games 200 --movetime 50 --concurrency 4
```

## 측정 결과 (이 저장소, 4코어 샌드박스, 단일 스레드 엔진)
- **0.3 vs 0.2**, 200판, 수당 50 ms, 동시 4판: **+161 =21 −18, 점수 85.8%, Elo +312 (95% 구간 +257 ~ +383), LOS 100%**.
  종료 사유: 체크메이트 179, 3회 반복 15, 기물 부족 3, 50수 2, 300수 제한 1. 충돌·불법 수 없음.
- `bench 6`(7개 포지션 고정 깊이 6): **0.2 = 7,509,353 노드 → 0.3 = 285,998 노드** (약 26배 감소, 노드 수는 결정적).
  NPS 는 3.8 M → 1.6 M 로 낮아졌지만(노드당 비용 증가) 시간은 1975 ms → 176 ms.
- 같은 중반 포지션에서 0.2 는 500 ms 에 깊이 6, 0.3 은 약 390 ms 에 깊이 11.
- `bench 9` = 1,991,314 노드(약 0.66 s) — 이후 버전의 회귀 기준선.
- 단위 테스트 60개: GCC Release, clang, ASan+UBSan, TSan 모두 통과. Perft 는 그대로 정확.

## 한계 (읽을 때 주의)
- **Elo 는 0.2 대비 상대값**이다. 같은 계열 엔진끼리의 짧은 시간 대국이라 실제 강도 향상을 과대평가하는 경향이 있고,
  외부 엔진 대비 절대 Elo 는 측정하지 않았다.
- 수당 50 ms, 오프닝 16개로 측정했다. 긴 시간 제어에서는 달라질 수 있다.
- 기능별 효과(TT 만, LMR 만 등)는 분리해 측정하지 않았다. 개별 효과는 0.5 에서 SPRT 로 확인한다.
- 평가 함수는 여전히 단순(material + PST)해서 전략적 판단은 약하다. 0.4 의 과제.
- 스레드는 `std::thread` 직접 사용. WASM 단일 스레드 빌드를 위한 `platform/` 격리는 아직이다.
