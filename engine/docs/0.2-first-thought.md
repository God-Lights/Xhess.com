# Albatross 0.2 "First Thought" — 설계 기록

범위: 스스로 수를 계산해 실제 대국이 가능한 엔진. Negamax + Alpha-Beta, Iterative Deepening,
Quiescence Search, 기본 HCE(material + PST), UCI `go`(시간 관리 포함). 아래는 **구현된 결정**과 측정 결과다.

## 모듈과 의존성

```
core ← eval (evaluation.h / classical.cpp)
core, eval ← search (search, movepick, timeman, limits)
search ← uci
```

Search 는 `eval/evaluation.h` 의 `int evaluate(const Position&)` 만 알고, 평가 구현(HCE → NNUE)은
링크 대상만 바꿔 교체할 수 있다.

## 탐색
- **Negamax + alpha-beta** (fail-soft), **iterative deepening**: 매 깊이 완료 후 `info` 출력, 이전 깊이의 최선수를
  루트에서 먼저 탐색. 중단된 깊이는 불완전하므로 버리고 직전 결과를 쓴다(깊이 1 이전 중단에 대비해 첫 합법 수를 폴백으로 보관).
- **Quiescence**: stand-pat + 캡처/승급만. **체크 중에는 모든 회피 수**를 탐색해 지평선 효과로 인한 메이트 오판을 막는다.
- **수 정렬**: MVV-LVA 캡처 → 승급 → 나머지. 후보를 선택 정렬로 하나씩 뽑는다(베타 컷이 빨라 전체 정렬보다 저렴).
  Killer/History/TT 수는 0.3.
- **메이트 점수**: `MATE - ply`(가장 짧은 메이트 선호). UCI 로는 `score mate N`(N 은 수, 음수 = 당함).
- **무승부**: 탐색 중 2회 반복(게임 이력 포함), 50수(100 half-move), 기물 부족은 0점. 메이트가 50수 규칙보다 우선.
- **종료 상태**: 수가 없으면 `info depth 0 score mate 0`(체크메이트) 또는 `score cp 0`(스테일메이트) 뒤에 `bestmove 0000`.
- 이 버전에 **없는 것**: TT, killer/history, PVS, LMR, null move, aspiration, SEE, delta pruning, check extension (0.3 이후).

## 평가 (HCE 0.2)
기물 가치 100/320/330/500/900 + 기물별 PST. 킹 PST 만 비폰 기물량(phase 24 → 0)으로 중반/종반을 보간한다.
전체 tapered evaluation 과 폰 구조·킹 안전·기동성 등은 0.4. PST 값은 손으로 쓴 출발점이며 이후 셀프플레이로 튜닝한다.

## 시간 관리 (`timeman`)
- `movetime`: 그대로 사용. 시계(`wtime/btime/winc/binc/movestogo`): `base = 남은시간/30(또는 movestogo) + 증분×3/4`,
  soft = `min(base, 가용/2)`, hard = `min(3×base, 가용×0.7)` (가용 = 남은시간 − 20 ms).
- soft: 한 깊이가 끝난 뒤 경과 시간이 soft 의 절반이면 다음 깊이를 시작하지 않는다(다음 깊이는 보통 지금까지와
  비슷하거나 더 오래 걸려 중간에 잘리기 때문). hard: 실행 중인 깊이를 중단. 노드 한도/stop 과 함께 2048 노드마다 확인.
- `depth`, `nodes`, `infinite` 탐색은 시간 제한이 없다. `go infinite` 는 `stop` 전에 `bestmove` 를 내지 않는다.

## UCI
`go` 는 워커 스레드에서 실행되어 탐색 중에도 `isready`/`stop`/`quit` 에 응답한다. 모든 출력은 하나의 뮤텍스로 직렬화.
지원: `depth nodes movetime wtime btime winc binc movestogo infinite perft`. 입력이 끝나면 유한한 탐색은 끝까지 기다리고
무한 탐색은 멈춘다. `setoption` 은 받기만 한다(Hash/Threads/MultiPV 는 이후).
`bench [depth]`: 7개 포지션 고정 깊이 탐색. 노드 수는 결정적이라 의도치 않은 탐색 변화를 잡는 지문으로 쓴다.

## 이번 버전에서 함께 고친 것
- 시작 시 magic 탐색(~330 ms)을 제거: 같은 생성기로 구한 번호를 상수로 내장(`uciok` 지연 336 ms → 약 4 ms).
  내장 값은 테이블을 채우며 충돌 검사하고, 실패하면 기존 탐색으로 대체한다(번호를 일부러 망가뜨려 대체 경로 동작 확인).

## 검증 결과 (이 저장소에서 실제 측정)
- 단위 테스트 50개 통과: GCC 13 Release, clang Release, ASan+UBSan Debug, TSan Debug.
- 전술 테스트: 백랭크/스칼라 메이트 1수, 메이트 2수(`Ra6!`)를 올바른 점수와 첫 수로 발견, 공짜 기물 획득, 퀸 헌납 회피,
  K+Q vs K 에서 스테일메이트 회피, 막다른 국면 처리, 반복·기물 부족 0점, PV 가 합법적 수열.
- 셀프플레이 8판(수당 40 ms): 불법 수·비정상 종료 없음. 7판 체크메이트, 1판 300수 제한.
- 시간 제어: `go movetime 200` < 600 ms 이내 응답, `wtime 100` 에서 6 ms 만에 응답, `stop` 은 1초 이내 반영.
- `bench 6`: 7,509,353 노드 (노드 수는 결정적), 이 샌드박스(단일 스레드)에서 약 4.0 M nps.
  중반 포지션에서 500 ms 에 깊이 6. 이 수치는 **TT/가지치기 도입(0.3) 전후 비교의 기준선**이며, 강도(Elo)는 측정하지 않았다.
- Perft 는 0.1 과 동일하게 정확(시작 포지션 depth 5 = 4,865,609).

## 남은 일 / 알려진 한계
- 탐색 깊이가 얕다(위 수치). 0.3 에서 TT, killer/history, PVS, LMR, null move 로 개선하고 엔진 간 대국(SPRT)으로 검증한다.
- Elo 미측정: 외부 엔진과의 대국 인프라(fastchess/cutechess)는 0.5 에서 갖춘다.
- 스레드는 `std::thread` 직접 사용. WASM 단일 스레드 빌드를 위해 이후 `platform/` 으로 격리해야 한다.
