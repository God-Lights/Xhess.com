# Albatross 0.5 — tuning infrastructure (and a negative result)

## What was built
- `src/eval/params.def` — every evaluation weight in one X-macro list. The normal build compiles it to constants (no speed cost: `bench` node count and NPS unchanged).
- `albatross_tunable` — same engine with a runtime weight registry and the UCI option `EvalOverride` (`name=value,...`, e.g. `doubledPawn.mg=0,doubledPawn.eg=0`). Used for ablation matches: `tools/match.py --b-opt EvalOverride=...`.
- `albatross_datagen` — self-play data (random openings within ±250 cp, 5000 nodes/move, quiet positions only, win/draw adjudication). `<fen> | <result>` lines.
- `albatross_tuner` — Texel tuning: fitted K, coordinate descent over 541 weights, train/validation split, best-validation snapshot; anchors (pawn = 100) and non-linear parameters excluded. Rare endgame terms (`unstoppablePasser`, `mopUp*`) are frozen: quiet self-play barely contains them and the first run drove `unstoppablePasser` 450→171 and `mopUpEdge` negative.
- `tools/apply_params.py` writes tuned values back into `params.def`, keeping comments.

## Result
12,000 games, 455,865 positions, 6 passes (28 min on 4 threads). Validation loss 0.10824 → 0.10420 (−3.7%).

Match rules: 400 games, 50 ms/move, 16 openings × both colours, adopt only if the 95% interval is above 0.

| candidate vs hand-set weights | score | Elo | 95% interval | LOS |
|---|---|---|---|---|
| all tuned weights | 44.9% | −36 | [−67, −5] | 1.2% |
| tuned, material restored | 38.6% | −80 | [−112, −50] | 0.0% |

**Decision: tuned weights were not adopted.** `params.def` keeps the hand-set values. A lower Texel loss did not translate into playing strength here; likely causes are labels from the engine's own shallow self-play (circular), the quiet-position filter removing exactly the tactical positions where evaluation matters in play, and mg/eg terms trading off against each other in ways a static-eval loss cannot see. Next ideas: label with a stronger/external source, tune fewer groups at a time (PST only, etc.) and ablate each group with `EvalOverride`, and use game-play based tuning (SPSA).
